# serve-net v0.8.0

**Trust at the edges.** This release fixes what an independent review of 0.7.1 found, each with a test that fails without the fix. The two that matter most are on the edges a client controls. On a TLS listener, a client could ask the TLS layer for one host and the request for another, and serve-net served the second; a TLS acceptor that requires client certificates for one host could be stepped around that way. WebSocket upgrades accepted a page from any site, so a browser's cookies could carry another site's page into a socket. Both are closed by default now. The release also brings the 0.8 work: ws-net 0.9, net-io 0.7.1, a soft cap that follows the descriptor limit, the first custom protocol family, and `docs/ARCHITECTURE.md`.

FastCGI, net-io 0.8, and the two-week production site that 0.8.0 was to wait for move to 0.9.0 (D-112): none of them has a date, and the fixes below should not wait for them.

## Security

- **The host is the TLS host (T-42).** On a listener serve-net decrypts, a request whose `Host` names another host than the server name the client sent in the TLS handshake is answered `421 Misdirected Request` before `head` runs. Names are compared without letter case, a port, or one trailing dot. `ListenerSpec::allow_sni_mismatch(reason)` turns the check off for a listener whose hosts all share one TLS policy. The handshake's facts now reach the service: `Envelope::tls()` gives the server name, the ALPN result, the version, the cipher suite, and the SHA-256 of a verified client certificate's public key. Affects 0.4.0 to 0.7.1 with `Ingress::DirectTls`. Cost: one comparison of two short strings per request on a TLS connection, about 10 ns [est.].
- **WebSocket upgrades are same-origin by default (T-41).** A page on another origin is answered 403 before the 101 (`WebSocketTarget::origins`, ws-net's `OriginPolicy`). Affects 0.6.0 to 0.7.1 with feature `ws`.
- **A panic costs its connection and nothing else.** A panic in `done` or the observer kept the request's admission for the life of the server; admission is now released through a guard. A panicking WebSocket handler with `catch_service_panics` off skipped `closed`, left its senders open, and stayed in the drain registry; the close now cleans all three up. `catch_service_panics` now covers `head`, `done`, and `upgraded` as well as `call`.
- **A slow reader cannot hold a copy of the body.** A reply body was copied whole into the connection's output buffer and kept until the client read it: eight stalled clients of an 8 MiB `body_static` held 64 MiB. The body is now sent from where the service put it (`Family::reply_body`), and a slow reader holds at most the output budget. This also removes one copy of every reply byte.
- **`max_deferred_per_worker` caps parked requests (T-26).** It only sized net-io's completion queue. Past the cap a deferral now gets the busy refusal, and its token can only expire.
- **`PublicBind` sees passed-in sockets.** An inherited listener's fallback address is checked at build, and the address of a socket passed in by systemd or a supervisor at bind, before the door opens.
- **Wiping reaches more copies.** On a wiping profile a buffer that grows zeroes the block it leaves, a deferred reply that is never sent is zeroed, and an offloaded request's body and a `DetachedHead` are zeroed when dropped.

## Changed

- **A reload that changes net-io's limits on a kept listener is refused.** net-io fixes a listener's transport limits when it binds it (`write_stall`, `min_rate`, `max_pending_output`, `linger`, keep-alive idle, the read timeout, its hard and per-source caps), and a reload that changed them was reported as applied while nothing took effect. It is now refused with `ReloadListener`; re-add the listener under a new name, or restart. Moving a kept listener between direct and forwarded ingress changes two of them, so it is refused too.
- **`Running::drain` is bounded.** It waits at most 5 s past its deadline for net-io's shutdown, and returns with `DrainReport::stuck` set when a worker never came back.
- **ws-net 0.9 and net-io 0.7.1.** `ws_net` and `net_io` types are part of serve-net's API, so code that names them moves with it. With no `max_connections`, the reactor's soft cap now follows the process's descriptor limit (D-108).
- **One family per server.** `bind` refuses a listener whose profile names a custom engine, and `bind_family` with a custom family refuses an HTTP profile (`RuleId::EngineFamily`, D-110).
- An accept reads the server's tables through its worker's own cache instead of taking a lock all workers share.

## Fixed

- `BodyPolicy::Discard { max }` counted the head toward `max`.
- After a panic in `call`, `Running::health` reported the worker stalled while it was idle.
- A gate that denied the 101 of a WebSocket upgrade closed the connection with nothing written (D-105).
- The docs presented FastCGI as available; it is planned for 0.9.0.

## Added

`Envelope::tls`, `HeadContext::tls`, `HeadContext::checks_sni`, `ListenerSpec::allow_sni_mismatch`, `RefusalKind::Misdirected`, `RefusalKind::CrossOrigin`, `WebSocketTarget::origins`, `Family::upgrade_allowed`, `Family::reply_body`, `Profile::wipes_buffers`, `RuleId::EngineFamily`, `DrainReport::stuck`, and `docs/ARCHITECTURE.md`.

## Upgrading from 0.7

1. Change the version to `0.8` and move code that names `ws_net` or `net_io` types to ws-net 0.9 and net-io 0.7.
2. A TLS listener now answers 421 when `Host` differs from the TLS server name. If clients reach several hosts on one connection and every host has the same TLS policy, add `allow_sni_mismatch` with the reason.
3. A WebSocket whose pages live on another origin needs `WebSocketTarget::origins(OriginPolicy::allow(..))`.
4. A reload that changed a kept listener's transport limits now fails; re-add the listener under a new name instead.
5. A server for a custom family gives profile 0 `EngineChoice::Custom`.

## Known issues

- net-io's security releases on its 0.7 line are announced but not published; 0.8.1 takes them the day they are on crates.io.
- An offload job's copy of the request head is http-net's, which cannot be zeroed; the body copy is (in the register).
- A drain waits at most 250 ms for open WebSockets to send their 1001; a starved worker can miss it until net-io 0.8's `on_drain`.
- `test_i9_kill_after_the_door_closed` has failed twice on Windows: requests begun in the few milliseconds after a hand-off's kill were answered `503` with `Retry-After: 1` instead of served. The cause is not yet known; the test now records which server refused (in the register).
