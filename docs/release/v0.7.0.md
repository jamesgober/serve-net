# serve-net v0.7.0 - Hardening

**Proven under attack, and under a day of load.** v0.7.0 adds TLS with an engine chosen by ALPN, WebSocket sends from any thread, and an idle connection that costs about 4 KB, and it closes every finding of an adversarial review with a test that fails without its fix.

## What's new

- **TLS end to end, and the engine by ALPN.** `EngineChoice::Http1OrH2ByAlpn` runs HTTP/1.1 for `http/1.1` or no ALPN. Every profile's ALPN result is now checked when a TLS connection opens: a protocol with no engine (`h2`, until the HTTP/2 engine exists) is closed with `EndReason::NoEngine` before a byte reaches an engine. Tested end to end with tls-net 0.5.
- **WebSocket sends from any thread.** `WebSocketConn::sender()` gives a `WsSender` that queues messages, bounded by the connection's output budget, for the connection's worker to write. A drain now closes open WebSockets with 1001 before it ends them.
- **About 4 KB per idle connection.** A keep-alive connection that stays quiet for a second gives its buffers back: 3,116 bytes on macOS and 3,909 on Linux for 10,000 idle connections, from about 9 KB. On Windows net-io's completion-port bookkeeping adds about 150 bytes (4,153).
- **A time bound per WebSocket message** (`WebSocketTarget::message_timeout`, 30 s by default): a message trickled to hold its buffer open closes with 1008.
- **The gate's tag on the envelope.** `Envelope::gate_tag()` returns the `GateTag` the gate gave the connection in `Gate::admit`, on every request of the connection, so a gate integration no longer keeps its own map from connection id to tag. Cost: 8 bytes per connection (the envelope goes from 120 to 128 bytes on 64-bit targets) and one copy when the connection opens; nothing per request.
- **`docs/SECURITY.md`**: the trust boundaries, the defaults, a deployment checklist, and what serve-net does not defend; and a root `SECURITY.md` for reports.

## Hardening

- **An adversarial review** found seven defects; each is fixed with a test that fails without the fix. Three affected released versions and shipped in 0.6.3 ([GHSA-jcp7-qqq6-xw24](https://github.com/jamesgober/serve-net/security/advisories/GHSA-jcp7-qqq6-xw24)). The others: V-24 (scheme or host trust on a source that cannot carry them) is now refused at build; forwarded headers on a Unix socket open to any local peer raise a warning; a reload's body limit reaches a streamed body on an open connection; and the WebSocket message bound above.
- **A 24-hour soak** on net-io 0.6.2: SOAK_RESULT.
- **Every threat has an attack test** except T-19, which waits for FastCGI: descriptor exhaustion, large replies on many connections, the timer flood, IPv4-mapped addresses, the socket mode, and the rest.
- **Kill-at-every-step restarts**: the old server killed at four points of a hand-off under load; no connection refused, nothing begun after the kill lost.
- **The leak test**: 100,000 connections opened and closed, the heap flat.
- **Loom models** for the drain and the WebSocket sender. One found a race in which a drain could wait its full goodbye time for a connection that had closed; fixed.

## Performance

serve-net against hyper with hyper-util on a hosted runner: level on connection churn, 1.7% behind at 256 keep-alive connections, 8 to 9% behind with 1,000 connections or 16-deep pipelining (`docs/PERFORMANCE.md`). The target is 20% ahead; it blocks 1.0, and the pre-1.0 performance pass starts from these numbers.

## Known issues

- **Throughput against hyper**, as above.
- **Restarts on Windows (T-30)**: tested on Linux and macOS only.
- **Idle memory on Windows** is about 4.15 KB against a 4 KiB target.
- **A drain started only on the owner's own control line** closes a quiet WebSocket without a 1001.
- **A wiping profile does not zero ws-net's buffers**, and a gate that denies the upgrade request after the 101 is decided closes instead of answering 403.

Each is in the pre-1.0 register in `dev/ROADMAP.md`.

## Moved to 0.8.0

FastCGI (Linux and macOS first), T-19, and the `fastcgi_mapping` fuzz target wait for fcgi-net.

## Upgrading from 0.6.3

serve-net now requires net-io 0.6.2, whose drain never cuts a request that has already arrived. `EngineChoice` and `RuleId` gain variants (both non-exhaustive). An `Http1` profile closes a TLS connection that negotiated `h2` instead of answering it 400. A build that set `trust_scheme` or `trust_host` on a single-address header or PROXY v1 source is now refused, because those sources carry neither.
