# serve-net v0.8.4

**A connection that never speaks is not a slow peer.** Browsers open a spare connection ahead of need and often never send anything on it. serve-net ran the inbound rate check from accept, so that socket closed as a slow peer after 5 s, and a connection gate in front could count every page load against the visitor and ban repeat visitors.

The rate check now starts with the first byte. A silent connection closes on the head deadline (`head_timeout`, 10 s from accept by default), which is not a slow-peer close. A peer that sends a byte and then stalls is still closed as a slow peer, as before. This holds over TLS and on both drivers.

No API change. Upgrade by changing the version to `0.8.4`.
