# serve-net v0.6.3

**Three security fixes from an adversarial review.** Upgrade if you use WebSocket upgrades, the RFC 7239 `Forwarded` source with `MissingHeader::UsePeer`, or PROXY listeners with `trust_scheme`. There is no API change.

## Security

- **A request smuggled after a WebSocket upgrade.** Input the HTTP engine had not yet taken in the read that carried the upgrade request was fed back to it after the 101 and parsed as a new HTTP request. A client could put a request behind about 64 KiB of WebSocket frames and have it reach `call`. Behind a trusted proxy, which forwards an upgraded connection as a tunnel and adds no forwarded fields, that request's own `X-Forwarded-For` was believed, so the client chose its address. It needs net-io to read more than the HTTP engine's free buffer at once: above net-io's default 16 KiB read size, or the test transport. Affects 0.6.0 to 0.6.2 with feature `ws`.
- **`X-Forwarded-*` believed for an RFC 7239 source.** With `ForwardedSource::Forwarded` and `MissingHeader::UsePeer`, a request from a trusted peer with no `Forwarded` element had `X-Forwarded-Host` and `X-Forwarded-Proto` believed at `head`. An RFC 7239 proxy neither sets nor strips those fields, so a client behind it chose the host and scheme `head` saw (`call` saw the `Host` field). Affects 0.3.0 to 0.6.2 with that source, `UsePeer`, and `trust_host` or `trust_scheme`.
- **Plain clients reported as https behind PROXY v2.** A PROXY v2 SSL TLV marked the client `https` whenever it was present. A proxy that sends the TLV on every connection (HAProxy's `send-proxy-v2-ssl`) sets the `PP2_CLIENT_SSL` bit only for TLS clients, so a client on plain HTTP was reported as `https`. Affects 0.4.0 to 0.6.2 on PROXY listeners with `trust_scheme` on.

Each fix has a regression test that fails without it: `tests/websocket.rs`, `tests/threats.rs`, and `tests/loopback.rs`.

Advisory: [GHSA-jcp7-qqq6-xw24](https://github.com/jamesgober/serve-net/security/advisories/GHSA-jcp7-qqq6-xw24). serve-net 0.6.2 is yanked from crates.io (0.3.0 to 0.6.1 already were, for [GHSA-7vvv-g6cw-p8gj](https://github.com/jamesgober/serve-net/security/advisories/GHSA-7vvv-g6cw-p8gj)).

## Upgrading from 0.6.2

Change the version to `0.6.3` and run `cargo update -p serve-net`. Nothing else changes.
