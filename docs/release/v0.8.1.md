# serve-net v0.8.1

**net-io's security release.** serve-net now requires net-io 0.7.2, which fixes two critical and three high defects an independent review of net-io found (D-113). serve-net's own code is unchanged.

## Security

net-io 0.7.2 fixes:

- **Windows, reactor, named pipes (critical).** A gate's denial of a write on a named-pipe connection could crash the process or corrupt its memory.
- **Windows listener hand-off (critical).** A forged hand-off message could give a socket two owners or close it.
- **Reactor with TLS (high).** Silent TLS connections could hold the shared buffer budget and stall every other connection.
- **Unix sockets (high).** Binding in a directory other users can write to set the mode and owner by path, which a link could point at another file.
- **Windows named pipes (high).** A pipe name could open a file or a network path.

## Changed

- A Unix listener in a directory every user can write to, without the sticky bit, is refused at bind (net-io's `ConfigReason::InsecureDirectory`). Put the socket in a directory only the service's user can change, such as `/run/<service>`.

## Upgrading

Change the version to `0.8.1`. Nothing else changes. On serve-net 0.7, `cargo update -p net-io` takes net-io 0.6.3 with the same fixes, but 0.7 also has the two high defects fixed in 0.8.0: move to 0.8.
