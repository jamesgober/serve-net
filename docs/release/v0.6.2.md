# serve-net v0.6.2

**A security fix for servers behind forwarded headers that trust the proxy's host.** Upgrade if any listener uses `ProxySource::trust_host(true)`. There is no API change.

## Security

- **An untrusted client could set the authority a service saw in `call`.** With `trust_host(true)` on a listener behind forwarded headers, a client that was not a trusted proxy could send `X-Forwarded-Host` or `Forwarded: host=` and have that value reported by `HttpHead::authority()` inside `call`. The forwarded walk was right, so `head` saw the `Host` field as it should, but the view of the request built again for `call` took the host field without checking that the walk had passed a trusted hop. A service that routes virtual hosts, builds absolute links, or keys a cache by authority in `call` could be steered by any client that reached the listener directly. The client address and the scheme were not affected. Affects 0.3.0 to 0.6.1; listeners with `trust_host` off, direct listeners, and PROXY listeners are not affected.

  Found by a new fuzz target, `forwarded_proto_host`, whose oracle now also requires `head` and `call` to see the same request.

## Added

- **Attack tests** in `tests/threats.rs` for slow readers (T-3), a pipelining flood of 10,000 requests (T-6), a request smuggled in an unread body (T-8), forwarded fields on a direct listener (T-13), host and scheme spoofing (T-17), a request kept open through a drain (T-29), information in refusals (T-34), and control bytes in forwarded addresses (T-35).

## Upgrading from 0.6.1

Change the version to `0.6.2` and run `cargo update -p serve-net`. Nothing else changes.
