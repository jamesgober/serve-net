# serve-net v0.6.1

**A security fix through net-io, and an install that works again.** v0.6.1 moves serve-net to net-io 0.6. There is no API change: upgrade by changing the version.

## Security

- **Slow clients on the reactor.** net-io 0.5.0 did not apply the minimum transfer rate on the reactor to a peer that sent more often than the check interval (1 s by default). Each arrival moved the check later, so a client that sent one byte every 40 ms after an opening burst kept its connection for as long as it kept sending. The reactor is serve-net's default driver, so serve-net 0.5.0 and 0.6.0 were affected with default settings; the blocking pool was not. net-io 0.6 checks the rate on every arrival and every send completion, so `Limits::min_rate` holds again.

## Fixed

- **serve-net 0.5.0 and 0.6.0 could not be added to a new project.** Both require net-io 0.5, and net-io 0.5.0 is yanked for the issue above, so Cargo finds no version to select. A project with an existing lockfile still builds them, with the vulnerable net-io: update to 0.6.1.

## Upgrading from 0.6.0

Change the version to `0.6.1` and run `cargo update -p serve-net`. Nothing else changes.
