# serve-net v0.3.0 - Core

**The first working server.** v0.3.0 serves HTTP/1.1 over net-io 0.3's blocking driver, facing clients directly or behind a reverse proxy on the same host, with every default limit and defence on. One call starts it:

```rust
let server = serve_net::http("127.0.0.1:8080", |req, reply| {
    reply.text(200, &format!("hello from {}", req.path()));
})?;
server.wait();
```

## What's in 0.3.0

- **Tier 1.** `serve_net::http` and `serve_net::http_behind_proxy`, which takes the real client from `X-Forwarded-For` only when the connection comes from a trusted proxy, and refuses to start a trusting listener on a public address.
- **The builder.** Listeners, profiles, limits, keep-alive, workers, and every hook: admission, dispatch, revocation checkpoints, observation, the connection gate, the transport event sink, and the control line. `build` checks every rule and reports every failure at once; `bind` binds with the door closed (drop privileges here), `open` starts accepting.
- **Running and stopping.** `Running` with `drain`, `wait`, a `DrainHandle` for other threads, `close_door`, `stats` (per-worker counters plus net-io's), `health`, and `listeners`. A drain closes idle keep-alive connections at once, puts the close signal on replies in flight, and reports what it did.
- **Under load.** Soft connection caps answered with 503 and a jittered `Retry-After` before anything is read, net-io's hard caps above them, admission per profile (`InFlightCap`), keep-alive shortened when the pool is busy, and gate denials answered with a clean refusal.
- **Custom protocols.** The engine and family traits that HTTP/1.1 itself uses, and `bind_family` to run them.
- **Testing.** `serve_net::testing` runs a service against raw request bytes without sockets, including whole keep-alive connections.
- **Examples.** `hello` and `behind_proxy`.

## Proof

Loopback socket tests on Windows, Linux, and macOS (keep-alive, pipelining, a drain with a slow request in flight, a gate denial on the second reply of a connection, proxies, a leak test at the soft cap), the simulated-connection suite for every state of the connection machine, zero allocations per request in steady state (counting-allocator tests), property tests, fuzz targets, and loom models of the shared state.

On a shared development machine (numbers for comparing builds, not benchmarks): a keep-alive GET through the engine and the connection machine takes about 330 ns; over real loopback sockets a small demo served about 17,000 requests per second on one connection and 190,000 on 15, p99 under 0.4 ms.

## Upgrading from 0.2.0

0.2.0 held only `VERSION`. Everything else is new and follows `docs/API.md`.
