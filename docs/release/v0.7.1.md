# serve-net v0.7.1

**The busy refusal reaches the client.** A connection over the soft connection cap gets a 503 with `Retry-After`, written before anything is read. That connection was closed as an idle one, without the bounded linger that reads and discards what the client still sends, so the request on its way drew a reset. Windows drops a reply already received when a reset arrives, so the client saw an aborted connection instead of the 503, and a proxy in front would answer 502. There is no API change.

## Fixed

- **The busy refusal closes with its linger.** A refusal written before any request was read now marks the connection as sending, so net-io closes it the way it closes every other reply: FIN, then up to 2 s or 64 KiB of the client's input read and discarded (`Limits::linger`). Found by `test_loopback_rounds_at_the_soft_cap_leak_nothing` on the Windows blocking driver, where it failed in 9 of 40 local runs; 0 of 40 with the fix. The unit test `test_capacity_refusal_without_read` fails without it. Earlier versions write the refusal the same way.

Cost: a refused connection whose client keeps sending can now hold its place for up to the linger, inside the headroom between the soft and the hard cap; past the hard cap net-io resets as before. A client that reads the 503 and closes is released at once. Nothing changes per request.

## Upgrading from 0.7.0

Change the version to `0.7.1` and run `cargo update -p serve-net`. Nothing else changes.
