# serve-net v0.9.0 - HTTP/2

**HTTP/2, with every check HTTP/1.1 has.** A connection that negotiates `h2` in the TLS handshake is now served as HTTP/2 through h2-net 0.3.1, behind the new `h2` feature. Every stream is a request like any other: the same `head`, admission, checkpoints, and service, in its own `Envelope`. The release also lets a WebSocket be closed from any thread with the close handshake, which a revocation needs.

This is a minor version because of http-net 0.10, which serve-net re-exports. The beta planned for 0.9.0 moves to 0.10.0, with the same exit: two weeks on a production site, a real wrapper, and no API change across two beta releases. FastCGI moves with it.

## HTTP/2 (feature `h2`)

- **ALPN.** A profile with `EngineChoice::Http1OrH2ByAlpn` serves HTTP/2 when the handshake negotiated `h2`, and HTTP/1.1 otherwise.
- **One stream, one request.** Each stream reaches the service as an `HttpRequest` whose `RequestSeq` is the stream id. Deferred replies work per stream. A refused stream is answered with its status, and the rest of the connection goes on, so one bad request costs its sender no more than it costs the server.
- **Attacks end the connection as abuse.** h2-net's budgets stop rapid reset, `CONTINUATION` and control-frame floods, and a peer that sends but never reads. The connection then ends as the new `EndReason::Abuse`, which a connection gate can count against the address.
- **Limits come from the profile.** The header budget, the stream window (from the body limit, at most 256 KiB), and the output (`max_pending_output`).
- **Drain and stop.** A drain is HTTP/2's two-step `GOAWAY`; a stop closes at once.
- **Cleartext behind a trusted proxy.** `EngineChoice::Http1OrH2ByPreface` serves a connection as HTTP/2 when its first bytes are the HTTP/2 preface, for a proxy that speaks HTTP/2 to its backends. Validation refuses it on a listener that is not behind a trusted proxy (`RuleId::PriorKnowledgeWithoutProxy`), since on an open port it would let any client skip TLS. `Upgrade: h2c` is still never honoured.

Not yet: a streamed request body or a streamed reply over HTTP/2 (answered 501 and 500 with a `service_error`), and upgrades over HTTP/2.

## Closing a WebSocket from any thread

`WsSender::close(code, reason)` queues a Close after the messages already queued. The worker sends them, then the Close, and ends the connection when the client answers, or 5 s after the Close went out. A client that does not read, so the messages ahead of the Close never leave, is closed 5 s after the worker took the close. Sends are refused once a close was asked for. A second call, or a call after the connection closed, does nothing. The connection ends as `EndReason::ServiceClosed`, and the service hears `closed` with the code.

## Changed

- **http-net 0.10**, re-exported as `serve_net::http_net`. Code that uses the re-export directly follows http-net's migration guide: `Asked` is gone and `parse_response_head` takes the request's `Method`; incoming trailers no longer carry `content-length`, `transfer-encoding`, or `host`; `Debug` redacts more credential fields. Nothing in serve-net's own API changed.
- A request's state moved into an exchange record inside the connection, one per request in flight. No change in behaviour.

## Added

`EngineChoice::Http1OrH2ByPreface`, `RuleId::PriorKnowledgeWithoutProxy`, `EndReason::Abuse`, `WsSender::close`, and the `h2` feature.

## Upgrading from 0.8

1. Change the version to `0.9`.
2. If your code names `serve_net::http_net` types, follow http-net 0.10's migration guide.
3. For HTTP/2, turn on the `h2` feature and use `EngineChoice::Http1OrH2ByAlpn` on a TLS listener whose acceptor offers `h2`.
